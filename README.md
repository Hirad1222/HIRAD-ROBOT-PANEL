# HIRAD ROBOT PANEL

پنل مدیریت و نگهبانی گروه‌های **روبیکا**؛ رابط کاربری روی **GitHub Pages** و بک‌اند روی **Cloudflare Workers + D1**.

> **صداقت پیش از ظاهر:** این پنل هیچ وضعیت، آمار، گروه یا نتیجه‌ی ساختگی نشان نمی‌دهد. هر قابلیتی که API رسمی روبیکا آن را مستند نکرده باشد، با برچسب «در دسترس نیست» و دلیلش نمایش داده می‌شود و هرگز شبیه‌سازی نمی‌شود. فهرست دقیق در بخش [امکانات واقعی و محدودیت‌ها](#امکانات-واقعی-و-محدودیتها) آمده است.

## معماری

```
مرورگر شما (GitHub Pages)  ──HTTPS──►  Cloudflare Worker  ──HTTPS──►  Rubika Bot API
 HTML + CSS + JS خالص                   (احراز هویت، اعتبارسنجی،        botapi.rubika.ir/v3
 بدون build، بدون توکن                   محدودیت نرخ، لاگ ممیزی)
                                              │
                                              ▼
                                      Cloudflare D1 (SQLite)
                                      گروه‌ها، تنظیمات، اخطارها،
                                      تخلف‌ها، لاگ‌ها
```

- **فرانت‌اند:** بدون npm و بدون build. آدرس بک‌اند در فایل عمومی `assets/config.js` است (محرمانه نیست).
- **بک‌اند:** یک Cloudflare Worker (جاوااسکریپت ساده) با پایگاه‌داده‌ی D1.
- **ورود:** فقط یک رمز عبور (`ADMIN_PASSWORD`) که **سکرت کلودفلر** است. کاربر هرگز «کلید API پنل» یا «آدرس بک‌اند» تایپ نمی‌کند.
- **توکن ربات:** فقط در صفحه‌ی «اتصال ربات» وارد می‌شود، با HTTPS به Worker می‌رود، **رمزگذاری AES‑GCM** می‌شود (کلید: سکرت `TOKEN_ENC_KEY`) و هرگز به مرورگر برنمی‌گردد. جایگزین ایمن‌تر: ثبت توکن به‌صورت سکرت `RUBIKA_BOT_TOKEN` در کلودفلر (در این حالت اصلاً در D1 ذخیره نمی‌شود).

**چرا توکن در D1 (رمزگذاری‌شده) هم ذخیره می‌شود؟** Worker نمی‌تواند در زمان اجرا سکرت جدید بسازد مگر اینکه یک توکن مدیریتی کلودفلر را هم در خودش داشته باشد، که خطرناک‌تر است. پس دو حالت داریم: (۱) توکن رمزگذاری‌شده در D1 برای سادگی، یا (۲) سکرت `RUBIKA_BOT_TOKEN` برای حداکثر امنیت.

## امکانات واقعی و محدودیت‌ها

### ✅ واقعاً کار می‌کند (تست‌شده)

| قابلیت | توضیح |
|---|---|
| ورود امن | رمز = سکرت سرور؛ نشست امضاشده با انقضای ۱۲ ساعت؛ محدودیت ۵ تلاش در ۱۵ دقیقه؛ «خروج از همه‌ی نشست‌ها» |
| اتصال ربات | با متد رسمی `getMe`؛ فقط وقتی «متصل» نمایش داده می‌شود که روبیکا پاسخ بدهد |
| افزودن گروه | با شناسه‌ی چت (`chat_id`) و تأیید از طریق `getChat`؛ گروه نامعتبر ثبت نمی‌شود |
| تنظیمات هر گروه | قوانین گروه، آستانه‌ی اخطار، سیاست اقدام، پیام‌های خوشامد/خروج، ۱۲ قانون نگهبان؛ همه در D1 |
| قوانین نگهبان | ضداسپم، ضدفلود، ضدلینک، ضدتبلیغات، ضدفحش، ضدتکرار، ضدمنشن، ضدایموجی، الگوی کلاهبرداری، پیام طولانی، محافظت مدیران — **الگو و شمارنده (regex)، نه هوش مصنوعی** |
| آزمایشگر قوانین (dry‑run) | یک پیام نمونه را با قوانین ذخیره‌شده می‌سنجد؛ هیچ چیز حذف یا ارسال نمی‌شود |
| اخطار | صدور/ابطال، شمارش اخطار فعال، گزارش رسیدن به آستانه، معافیت‌ها |
| حذف پیام | با متد رسمی `deleteMessage` و تأیید صریح (فقط اگر روبیکا به ربات اجازه بدهد) |
| ارسال پیام آزمایشی خوشامد | با متد رسمی `sendMessage` |
| گزارش کاربران، تاریخچه‌ی تخلف، لاگ ممیزی، آمار روزانه | همه از D1؛ فقط کارهایی که خود پنل ثبت کرده |
| ابزارها | ماشین‌حساب (بدون `eval`)، مبدل واحد، تاریخ شمسی، ساعت جهانی، **آب‌وهوا** (Open‑Meteo، با منبع و زمان مشاهده)، **مبدل ارز** (ExchangeRate‑API، با منبع و زمان به‌روزرسانی)، معما، حدس عدد، سنگ‌کاغذقیچی، دانستنی |
| زبان و ظاهر | فارسی/انگلیسی با RTL/LTR، تم روشن/تیره، طراحی موبایل‑اول |

### ⛔ نیازمند پشتیبانی رسمی روبیکا (پیاده‌سازی **نشده** و شبیه‌سازی هم **نمی‌شود**)

صفحه‌ی رسمی متدهای روبیکا (`rubika.ir/botapi/methods`) این‌ها را ندارد:

| قابلیت | دلیل |
|---|---|
| **بن، آن‌بن، میوت (موقت/دائم)** | هیچ متد مستندی وجود ندارد. وقتی تعداد اخطار به آستانه برسد، پنل فقط «نیاز به اقدام دستی مدیر» را گزارش می‌کند و درخواست API (`/members/.../ban`) پاسخ `501 feature_unavailable` می‌دهد |
| کشف خودکار گروه‌ها | متدی برای فهرست‌کردن گروه‌های ربات نیست؛ گروه را با `chat_id` اضافه می‌کنید |
| فهرست اعضا / تشخیص مدیران گروه | متد مستند ندارد؛ «محافظت مدیران» با فهرست معافیت دستی کار می‌کند |
| حالت آهسته، قفل لینک/رسانه | متد مستند ندارد؛ مقدارها فقط ذخیره می‌شوند و اثری ندارند (در رابط هم همین گفته شده) |
| **نظارت زنده‌ی خودکار روی پیام‌ها** | `getUpdates` مستند است ولی ساختار شیء `Update` در صفحه‌ی متدها توضیح داده نشده؛ بدون حدس‌زدن فیلدها، این قابلیت فعال نشده است. تا آن زمان از «آزمایشگر» استفاده کنید |
| ارسال خودکار خوشامد/خروج | دریافت رویداد ورود/خروج ممکن نیست؛ فقط پیام آزمایشی دستی |
| ورود انبوه (join flood) | وابسته به رویداد ورود؛ منطق آن نوشته و تست شده ولی داده‌ای ندارد |
| سطح و جدول امتیاز کاربران | وابسته به جریان زنده‌ی پیام‌ها |
| قیمت طلا و نرخ بازار آزاد ایران | منبع رایگان و تأییدشده‌ای وصل نشده. مبدل ارز فقط نرخ مرجع جهانی است و **ریال را عمداً ندارد** |

> اتصال با توکن به‌تنهایی به همه‌ی گروه‌ها یا همه‌ی سطوح دسترسی مدیریتی نمی‌رسد؛ ربات فقط چت‌هایی را می‌بیند که به آن‌ها اضافه شده است.

## راه‌اندازی قدم‌به‌قدم از گوشی

همه‌چیز از مرورگر گوشی انجام می‌شود؛ نیازی به VS Code یا Node.js نیست. اگر صفحه‌های GitHub یا Cloudflare ناقص دیده شد، در مرورگر گزینه‌ی «Desktop site» را روشن کنید. همه‌ی سرویس‌ها پلن **رایگان** دارند و پول لازم نیست.

### ۱) حساب Cloudflare

1. در `dash.cloudflare.com` ثبت‌نام کنید (رایگان).
2. از منوی **Workers & Pages** وارد شوید. اگر از شما خواست، یک **زیردامنه‌ی workers.dev** انتخاب کنید (برای اولین انتشار لازم است).
3. **Account ID** را از همان صفحه کپی کنید (معمولاً در ستون کناری با عنوان «Account ID»).

### ۲) ساخت API Token در Cloudflare

1. **My Profile ← API Tokens ← Create Token**.
2. قالب **Edit Cloudflare Workers** را انتخاب کنید (اگر نام قالب‌ها در رابط Cloudflare فرق کرد، دسترسی‌های Workers Scripts و D1 را با سطح Edit بدهید).
3. در بخش Permissions یک ردیف اضافه کنید: **Account ← D1 ← Edit**.
4. توکن را بسازید و **همان لحظه کپی کنید** (بعداً دیده نمی‌شود). این توکن را برای کسی نفرستید.

### ۳) ثبت راز‌ها در GitHub

مخزن ← **Settings ← Secrets and variables ← Actions ← New repository secret**. این ۵ سکرت را بسازید:

| نام | مقدار |
|---|---|
| `CLOUDFLARE_API_TOKEN` | توکن مرحله‌ی ۲ |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID مرحله‌ی ۱ |
| `ADMIN_PASSWORD` | رمز ورود شما به پنل، **حداقل ۱۲ نویسه** |
| `SESSION_SECRET` | یک رشته‌ی تصادفی **حداقل ۳۲ نویسه** (با مولد رمز گوشی/مدیر رمز بسازید) |
| `TOKEN_ENC_KEY` | یک رشته‌ی تصادفی **حداقل ۳۲ نویسه**، متفاوت از قبلی |

> مقدار هیچ‌کدام را در فایل یا چت ننویسید. اگر سکرتی کم باشد، workflow پیش از دست‌زدن به Cloudflare متوقف می‌شود و می‌گوید کدام کم است.

### ۴) انتشار Worker

1. مخزن ← **Actions ← Deploy Cloudflare Worker ← Run workflow**.
2. صبر کنید تا سبز شود. این workflow: تست می‌گیرد، پایگاه‌داده‌ی D1 را (اگر نبود) می‌سازد، مهاجرت‌ها را اجرا می‌کند، Worker را منتشر می‌کند، سکرت‌ها را ثبت می‌کند و در پایان `/api/health` را بررسی می‌کند.
3. در **Summary** همان اجرا، آدرس Worker (مثل `https://hirad-robot-panel.xxx.workers.dev`) نوشته شده است.

### ۵) تنظیم آدرس Worker برای فرانت‌اند

مخزن ← **Settings ← Secrets and variables ← Actions ← Variables ← New repository variable**:
نام `WORKER_URL`، مقدار = آدرس مرحله‌ی ۴ (بدون `/` پایانی). این مقدار محرمانه نیست.

(روش جایگزین: فایل `assets/config.js` را ویرایش کنید و `API_BASE_URL` را بنویسید.)

### ۶) فعال‌سازی GitHub Pages

1. **Settings ← Pages ← Build and deployment ← Source: GitHub Actions**.
2. **Actions ← Deploy frontend to GitHub Pages ← Run workflow**.
3. پنل در `https://hirad1222.github.io/HIRAD-ROBOT-PANEL/` باز می‌شود.

> `ALLOWED_ORIGINS` در `worker/wrangler.toml` روی `https://hirad1222.github.io` تنظیم است (فقط مبدأ، بدون مسیر). اگر از دامنه‌ی دیگری استفاده می‌کنید همان‌جا اصلاحش کنید؛ `*` هرگز پذیرفته نمی‌شود.

### ۷) اولین ورود

1. پنل را باز کنید؛ در داشبورد فرم ورود را می‌بینید. با `ADMIN_PASSWORD` وارد شوید.
2. صفحه‌ی **اتصال ربات** ← توکن ربات را وارد کنید.
3. صفحه‌ی **گروه‌ها** ← `chat_id` گروه را وارد کنید (ربات باید عضو آن گروه باشد).
4. در **نگهبان** قوانین را روشن کنید (به‌جز «محافظت مدیران»، همه به‌طور پیش‌فرض خاموش‌اند) و با **مدیریت اعضا ← آزمایشگر** رفتارشان را امتحان کنید.

## اتصال امن ربات روبیکا

1. ربات را از ابزار رسمی ساخت ربات روبیکا بسازید و توکن را بگیرید.
2. **توکن را در چت، گیت‌هاب، ایشو یا فایل نگذارید.** فقط در فیلد «توکن ربات» صفحه‌ی اتصال بچسبانید.
3. پنل توکن را به Worker می‌فرستد، از روبیکا با `getMe` می‌پرسد «این ربات کیست؟» و فقط اگر روبیکا پاسخ بدهد «متصل» نشان می‌دهد. در غیر این صورت «خطا» نمایش داده می‌شود.
4. فیلد بلافاصله خالی می‌شود؛ توکن در `localStorage`، `sessionStorage`، کوکی یا DOM نمی‌ماند (تست مرورگری این را بررسی می‌کند).
5. **حداکثر امنیت (اختیاری):** در Cloudflare ← Workers ← `hirad-robot-panel` ← Settings ← Variables and Secrets، سکرت `RUBIKA_BOT_TOKEN` را اضافه کنید. در این حالت توکن اصلاً در D1 ذخیره نمی‌شود. برای قطع کامل، آن سکرت را هم از کلودفلر حذف کنید.
6. «قطع اتصال» توکن رمزگذاری‌شده را از D1 پاک می‌کند.

## امنیت

- توکن ربات و هر رازی **هرگز** در فرانت‌اند، GitHub Pages یا مخزن نیست؛ تست خودکار (`tests/security.test.js`) این را در هر CI بررسی می‌کند.
- CORS فقط به مبدأ واقعی فرانت‌اند؛ درخواست مرورگری از مبدأ دیگر `403` می‌گیرد.
- همه‌ی بدنه‌ها اعتبارسنجی می‌شوند؛ JSON خراب → `400`، بدنه‌ی بزرگ → `413`؛ شناسه‌ها با الگوی سخت‌گیرانه؛ شناسه‌ی گروه فقط اگر قبلاً از روبیکا تأیید شده باشد پذیرفته می‌شود.
- محدودیت نرخ (در D1، مشترک بین همه‌ی نمونه‌های Worker) برای ورود، اتصال ربات، افزودن گروه، اخطار، حذف پیام و ...
- لاگ ممیزی برای کارهای حساس؛ توکن در پیام خطا و لاگ **ماسک** می‌شود؛ پاسخ خطا هرگز stack یا راز ندارد.
- رابط کاربری بدون `innerHTML`/`eval`؛ CSP بدون `unsafe-inline` و `unsafe-eval`.
- اقدام‌های مخرب (حذف پیام، حذف گروه، قطع اتصال) تأیید صریح می‌خواهند. هیچ بن دائمی خودکاری وجود ندارد.
- اگر `ADMIN_PASSWORD` یا `SESSION_SECRET` لو رفت: سکرت را در GitHub عوض کنید و workflow انتشار Worker را دوباره اجرا کنید؛ همه‌ی نشست‌ها باطل می‌شوند.

## عیب‌یابی

| نشانه | علت / راه حل |
|---|---|
| «پیکربندی نشده» | `WORKER_URL` تنظیم نشده یا Pages پس از تنظیم دوباره منتشر نشده (مرحله‌ی ۵ و ۶) |

| workflow انتشار Worker قرمز، «secret is not set» | همان سکرت ذکرشده را بسازید (مرحله‌ی ۳) |
| خطای زیردامنه‌ی workers.dev | یک‌بار در Cloudflare ← Workers & Pages زیردامنه را ثبت کنید |
| خطای احراز هویت Cloudflare | توکن مجوز **D1 Edit** و **Workers Scripts Edit** ندارد (مرحله‌ی ۲) |
| `rubika_rejected` هنگام اتصال | توکن اشتباه است یا روبیکا پاسخ نداد |
| `chat_unreachable` هنگام افزودن گروه | شناسه غلط است یا ربات عضو گروه نیست |
| «Rubika refused to delete» | ربات در آن گروه اجازه‌ی حذف پیام ندارد |
| ۴۲۹ | محدودیت نرخ؛ چند دقیقه صبر کنید |
| آب‌وهوا/ارز بارگذاری نشد | سرویس بیرونی در دسترس نبود؛ به‌جای عدد ساختگی، خطا نمایش داده می‌شود |

آزمون مرورگری، Worker واقعی را با D1 درون‌حافظه‌ای و یک جایگزین آزمایشی برای روبیکا اجرا می‌کند و فرانت‌اند واقعی را در Chromium می‌راند: حالت‌های «پیکربندی نشده/خطا/قطع/متصل»، ورود، اتصال ربات، نبودن توکن در حافظه‌ی مرورگر، رفتن به هر ۱۱ بخش، سوئیچ FA/EN و RTL/LTR، تم تیره، و نبود اسکرول افقی در عرض ۳۶۰ پیکسل.

> **توجه:** آزمون‌ها با روبیکا و Cloudflare واقعی انجام نشده‌اند (نیازمند توکن و حساب شماست). اتصال واقعی را خودتان در مرحله‌ی ۷ تأیید کنید.

## مرجع API

همه‌ی پاسخ‌ها `{ "ok": true, "data": ... }` یا `{ "ok": false, "error": { "code", "message" } }` هستند. مسیرهای محافظت‌شده سرآیند `Authorization: Bearer <نشست>` می‌خواهند.

| متد و مسیر | کار |
|---|---|
| `GET /api/health` | عمومی؛ وضعیت Worker/D1 و درست‌بودن پیکربندی (بدون راز) |
| `POST /api/auth/login` · `POST /api/auth/logout-all` · `GET /api/auth/me` | ورود و نشست |
| `GET /api/summary` · `GET /api/capabilities` | خلاصه و ماتریس قابلیت‌ها |
| `GET /api/bot` · `POST /api/bot/connect` · `/disconnect` · `/check` | ربات |
| `GET/POST /api/groups` · `POST /api/groups/:id/refresh` · `DELETE /api/groups/:id` | گروه‌ها |
| `GET/PUT /api/groups/:id/settings` | تنظیمات، قوانین، خوشامد |
| `POST /api/groups/:id/moderation/test` | آزمایشگر (dry‑run) |
| `GET/POST/DELETE /api/groups/:id/warnings` · `/exemptions` · `/reports` (+`PATCH`) · `GET/POST /violations` | مدیریت اعضا |
| `POST /api/groups/:id/messages/delete` · `/welcome/test` | حذف پیام و پیام آزمایشی |
| `POST /api/groups/:id/members/:uid/ban\|unban\|mute` | همیشه `501 feature_unavailable` |
| `GET /api/analytics` · `GET /api/audit-logs` | آمار و لاگ |

## باگ‌های رفع‌شده

**در نسخه‌ی قدیمی (FastAPI/SQLite):**

- فرانت‌اند از کاربر «Backend URL» و «Panel API Key» می‌خواست ← حذف شد؛ آدرس در `config.js` و ورود با رمز سرور.
- وضعیت ربات «آماده» و تعداد گروه «۰» ثابت و ساختگی بود ← فقط از بک‌اند واقعی.
- `/api/groups` آرایه‌ی خالی ثابت و `/api/summary` صفرهای ثابت برمی‌گرداند ← از D1 و با توضیح علت.
- تنظیمات نگهبان فقط در `localStorage` ذخیره می‌شد ولی «ذخیره شد» نشان می‌داد ← ذخیره در D1 با اعتبارسنجی.
- بک‌اند هر JSON دلخواه را برای هر شناسه‌ی گروه می‌پذیرفت ← طرح‌واره‌ی سخت‌گیرانه و گروه ثبت‌شده.
- بدون محدودیت نرخ، لاگ ممیزی و ماسک توکن ← افزوده شد.
- SQLite/FastAPI روی Cloudflare اجرا نمی‌شود ← Worker + D1.
- workflow قدیمی `create-project-files.yml` با دسترسی نوشتن، فایل‌های قدیمی را دوباره روی مخزن می‌ریخت ← حذف شد.

**در این بازبینی:**

- آیکون‌های نوار بالا (منو/تم/زبان) خالی دیده می‌شدند و دکمه‌ی منو روی دسکتاپ هم نمایش داده می‌شد ← اصلاح CSS.
- در صفحه‌ی اول فرم ورود نبود و کاربر باید دنبال آن می‌گشت ← فرم ورود (یا «پیکربندی نشده/بک‌اند در دسترس نیست») مستقیم در داشبورد.
- CSP به‌خاطر استایل‌های inline مجبور به `unsafe-inline` بود ← حذف شد.
- در موبایل عنوان صفحه به «D..» کوتاه می‌شد و toast روی نوار پایین می‌افتاد ← اصلاح شد.
- آزمون i18n الگوی ساخت کلید پویا را اشتباه می‌خواند ← اصلاح؛ اسکریپت `npm test` در Node 22 کار نمی‌کرد ← اصلاح.
- مبدل ارز با منبع و زمان به‌روزرسانی افزوده شد؛ ریال و طلا عمداً ارائه نمی‌شوند.
